# PATCHSET

The ledger of the experiments this fork runs. It records the diff against
upstream `faer`.

## Pending public API extension

- EXPERIMENT: owned `Mat::row_capacity/col_capacity` and
  `Col/Row/Diag::capacity` expose the current allocation metadata without private
  layout assumptions ([#284](https://github.com/tensor4all/faer/issues/284)).
  They change no allocation, numerical path or dispatch; public-contract and
  executable-example validation belong to the proposing PR. No performance
  claim or campaign adoption is made. [Design and verification scope](docs/worklogs/2026-11-06-owned-capacity-queries.md).

- EXPERIMENT: `SymbolicQr::raw()` exposes a read-only borrowed reference to the
  already public symbolic variant, enabling downstream algorithm inspection
  without private-layout assumptions (AtelierArith/Colmat.jl#2). This adds no
  numerical dispatch or allocation; focused public API and doctest validation
  are recorded in the proposing PR. No performance claim or adoption is made.

## Status legend

- **TODO** — not started. The issue column names the driving issue, or `—`.
- **EXPERIMENT** — being implemented on a branch. Breaking things is fine.
- **KEEP** — tensor4all keeps using it. Whether it goes upstream is a separate
  decision.
- **DROPPED** — tried and thrown away. The reason stays here.
- **HOLD** — not adopted and not dropped: the reason it stopped is still open, so it is kept
  where its branch and records are.

## Evidence class of the adopted changes (2026-10-19)

Every `KEEP` row states what kind of evidence stands behind it, because the campaign's acceptance
gate has changed and two kinds of adoption are now in the ledger.

* **Through the v2 comparator** (a baseline/candidate pair on a declared target set, with the
  unchanged upstream row as the machine-state control). Two rows: `0627828`, the block Householder
  apply's column split, whose control **passed** (0/96 cells outside their own range, median ratio
  0.9995); and `2000dd9`, the native GEMM flop floor, whose control **failed** 1/60
  (`gemm c64 f 64x64x64` 4T at 0.81 in the unchanged row) and was adopted anyway. That failure is
  the binary-layout effect the campaign measured separately - the ratios of the unchanged row over
  those 60 cells span 0.741-1.355 while their median is 1.000 - not evidence against the floor.
* **Pre-protocol adoption** (isolated drivers, paired, best of 4-21): the remaining performance
  `KEEP` rows. They predate the comparator and are kept, but no page or claim may cite them as a
  gated result, and re-measuring them as campaign pairs is a separate decision (faer-benchmark#20).
* **Correctness only** (tests, no timing): the SVD zero-subproblem boundary fix, the SVD secular-root stagnation fix, the EVD normalization,
  the unpivoted QR column skip, the empty block Householder apply, the `join_raw` width split, the SVD subnormal-deflation ordering fix, the SVD merge boundary rotation,
  the tridiagonal QR sweep's diagonal update (`#76`), and the native indexed/diagonal GEMM extents fix. A performance claim for the last one would need a
  declared cell that executes it, and there is none.

## Ground rules

- One experiment per branch. Keep the diff small enough to rebase onto an
  upstream release tag.
- No unrelated formatting churn or dependency bumps; every extra diff is a
  rebase cost.
- Every experiment carries its own test, run locally by whoever wrote it. The PR
  gate (build) is not a substitute for recording the result.
- Anything intended for upstream is cleaned up and reviewed separately before it
  is proposed.

## Released: `t4a-faer` 0.29.0 (2026-11-04)

`t4a-faer` 0.29.0; `t4a-faer-traits` stays 0.24.2 (no change in `faer-traits/`). Published from the
merge commit of the version bump PR, tagged `faer-v0.29.0`.

**A minor bump, not a patch.** Two changes are in it and only one of them is small:

* The sparse LU fix recorded in the ledger row for #236: the recursive dense panel triangular solve
  no longer carries `#[cfg(feature = "rayon")]`, so a build without the default feature set computes
  it instead of skipping it. The default feature set was never affected, which is why the ordinary CI
  lanes stayed green while `--no-default-features` builds returned wrong `partial_piv_lu` results from
  `n = 17` upward, in every release since 0.26.0. On its own this would have been a patch.
* #243, which landed four minutes before the version bump, adds a generic parameter to three solver
  entry points: `matrix_free::bicgstab`, `matrix_free::conjugate_gradient` and `matrix_free::lsmr` are
  now `fn ...<T: ComplexField, C: IterationControl>`. That is a breaking change for any caller that
  names the scalar type explicitly; `bicgstab::<f64>` fails to compile with

  ```
  error[E0107]: function takes 2 generic arguments but 1 generic argument was supplied
  ```

  `bicgstab::<f64, _>` or ordinary type inference both work. Rust does not allow a default on a
  function's type parameter, so the compatibility could only have been kept by taking the controller
  as `impl IterationControl` in argument position instead of as a named parameter.

An earlier version bump on this branch said 0.28.3 and described the release as having no public API
change. That was wrong: it was written against the tree before #243 merged. The number was changed to
0.29.0 and the description rewritten before anything was published, so no consumer ever saw 0.28.3.
The regression test for the sparse LU half is `faer/tests/sparse_lu_no_rayon.rs` (f32, f64, c32 and c64
at n = 0, 1, 3, 12, 40 over all three `SupernodalThreshold` choices), together with the
`--no-default-features` CI lane that came with it. The callback half is `faer/tests/iteration_control.rs`.
