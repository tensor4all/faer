# Single-matrix Pfaffian

## Decisions

- Partial pivoted Parlett–Reid reduction follows Wimmer, *Algorithm 923*
  (ACM TOMS 38(4), 2012; arXiv:1102.3440, §II.B and Appendix B).
  Only every other column needs elimination for the Pfaffian. Stored multiplier
  pairs accumulate `X Yᵀ − Y Xᵀ`; transposes do not conjugate complex inputs.
- Satyarth et al., arXiv:2411.09859v2, §§3.6–3.7, explains the ordered pivoted
  panel and parallel trailing update. This implementation chooses a 32-column
  panel; that choice has not yet been performance-validated. Pivot selection,
  pending-column updates, permutations and normalization remain serial.
- Each completed panel partitions the strict lower triangle into equal-area,
  contiguous column ranges with the existing `lower_area_split`. The existing
  derived cost gate, using the Bunch–Kaufman rate as a provisional proxy, chooses
  the active width. The caller-held Team runs those ranges through `team::run`;
  Seq runs the same block kernel with one participant. There is no new executor.
- Native SIMD uses the existing pulp runtime dispatch. Pivot ties choose the
  smallest row. The rank-two sum order and the final product tree do not depend
  on the number of team members or vector lanes. Ordinary floating-point fused
  arithmetic still need not match across different ISA implementations.
- The immutable-input API takes `MemStack` with a `pfaffian_scratch` query,
  rather than the issue's allocating two-argument sketch. This honors #111's
  no-per-call-allocation rule without adding an allocating wrapper or TLS cache.
  The strict lower triangle is authoritative; skew symmetry is a caller
  precondition, like adjacent symmetric factorizations. Zero pivots and
  nonfinite/underflowed results are errors. Scaled/log Pfaffians, inverse and
  batched APIs are outside this change.
- Numerical code was derived from published equations, not copied or translated
  from PfaPack, mvmc-rs, or xrq-phys/Pfapack. Only the latter repository's README,
  filenames and LAPACK license file were consulted for structure; this makes no
  claim that that license covers every file. No reference numerical source was
  imported; the tests use independently written recursive/congruence oracles.

## Verification conclusions and constraints

- Ten focused tests pass with both default features and `x86-v4`:
  f32/f64/c32/c64 recursive definitions through n=8 and determinant identities;
  known-Pfaffian congruences and forced nonadjacent swaps across panel boundaries;
  pivot ties and masked tails; invalid shape, singularity, nonfinite arithmetic,
  underflow and normal/subnormal scale cases; strided input with ignored NaN upper
  entries; input preservation; and scratch shortage. Extended-precision real and
  complex cases also pass. Oracle comparisons explicitly reject nonfinite
  operands rather than accepting an infinite relative-error bound.
- Seq and Team budgets 1/3/8/32 agree exactly on n=258 fixtures for all four
  native scalar types; dispatch counters verify real multi-participant column
  sections, not just a Team token.
  The existing process-wide allocation guard reports zero allocations during
  complete held-team Pfaffian calls (budgets 4/8/70), and verifies dispatch;
  it passes in default and `x86-v4` configurations.
- Three new doctests, no-default-features/no-std compilation and std-only build
  pass.
  Repository-wide Clippy remains blocked by deny-lint errors in unchanged code
  (the traits' `eq_op`, then old factorization SIMD index expansions with
  `--no-deps`); no lint suppression or unrelated fixes were added. The full
  inherited library test suite has not completed; the checks above are focused
  integration tests, not a claim that the complete upstream suite passed.
- Both tested configurations actually select `pulp::x86::v3::V3`: four f64 or two
  c64 values per SIMD vector on this EPYC 7702P. There is no AVX-512 execution
  evidence. The existing manifest unconditionally enables `pulp/x86-v3`; a
  scalar-only Cargo build is not exposed. No feature defaults were changed.
- Evidence is correctness-only, not performance adoption. No upstream revision
  has been timed. Four-way timings against Fortran, stable Julia and mvmc-rs,
  SIMD build comparisons, and the requested 1/8/32-thread scaling are pending.
  The requested multi-thread pinning conflicts with literal CPU4-only affinity;
  this host's four-core L3 domains also need an explicit exception for the
  requested 8/32-core measurements. Benchmark harness placement remains subject
  to the repository's faer-benchmark ownership rule. No speed or acceptance claim
  is made before these are resolved and the complete measurement is run.
